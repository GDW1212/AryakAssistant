## **AI 영양제 추천 및 복용 관리 서비스 PRD (Product Requirements Document)**

**프로젝트명: 알비서**
**작성일:** 2025-07-24

---

### **1. 개요 (Overview)**

**1.1. 프로젝트 요약**
'면역케어 AI'는 바쁜 현대인의 면역 건강 증진을 목표로 하는 서비스입니다. 사용자의 생활 습관, 식단, 건강 상태 등을 AI가 종합적으로 분석하여 개인에게 최적화된 영양제를 추천합니다. 또한, 추천된 영양제의 효능과 성분을 상세히 분석해주고, 꾸준한 복용을 돕기 위한 스케줄 관리 및 알림 기능을 제공하는 개인 맞춤형 헬스케어 솔루션입니다.

**1.2. 문제 정의 (Problem Statement)**

- **정보 과잉 및 신뢰성 부족:** 시중에 수많은 영양제 정보가 넘쳐나지만, 어떤 제품이 자신에게 맞는지, 정보가 신뢰할 만한지 판단하기 어렵습니다.
- **개인화의 부재:** 대부분의 영양제 추천은 성별, 연령 등 단순한 기준에만 의존하여 개인의 고유한 생활 습관이나 건강 상태를 반영하지 못합니다.
- **복용 관리의 어려움:** 여러 종류의 영양제를 구매하더라도 꾸준히 챙겨 먹는 것을 잊기 쉬워 효과를 보기 어렵습니다.
- **전문가 상담의 부담:** 영양에 대한 전문적인 상담을 받기에는 시간과 비용적인 부담이 큽니다.

**1.3. 목표 (Goals)**

- **사용자 목표:**
    - AI 분석을 통해 나에게 꼭 맞는 영양제를 쉽고 빠르게 추천받는다.
    - 추천된 영양제의 성분과 효능에 대해 명확하게 이해한다.
    - 알림과 스케줄 관리를 통해 영양제 복용을 습관화한다.
- **비즈니스 목표:**
    - 초기 사용자 1,000명 확보 (서비스 런칭 후 3개월 내)
    - 설문 완료율 80% 이상 달성
    - 복용 스케줄 기능 활성 사용자 비율 60% 이상 유지

### **2. 사용자 페르소나 (User Persona)**

- **이름:** 김민준
- **나이:** 32세
- **직업:** IT 기업의 마케터
- **특징:**
    - 잦은 야근과 불규칙한 식사로 만성 피로를 느낌.
    - 최근 환절기마다 감기에 걸리는 등 면역력이 떨어졌다고 생각함.
    - 영양제를 먹어보려고 하지만, 종류가 너무 많아 선택에 어려움을 겪음.
    - 스마트폰 앱 사용에 익숙하며, 데이터 기반의 합리적인 추천을 선호함.

    - "광고가 아니라, 정말 내 건강에 도움이 되는 성분이 뭔지 알려줬으면 해."
    - "아침마다 잊지 않고 영양제를 챙겨 먹도록 누가 알려주면 좋겠다."

### **4. 기능 명세 (Feature Specifications)**

**4.1. AI 건강 설문 (FE-02) & 분석/추천 (FE-03)**

- **User Story:** 사용자는 자신의 건강 상태와 생활 습관에 대한 질문에 답변함으로써, 개인 맞춤형 영양제 추천을 받고 싶다.
- **요구사항:**
    - 설문은 15개 내외의 핵심 질문으로 구성되어 사용자의 피로도를 최소화한다.
    - 질문 항목: 나이, 성별, 하루 평균 수면 시간, 주간 운동 횟수, 식습관(육류/채소 섭취 비율), 스트레스 수준, 주요 건강 고민(피로, 눈 건강, 피부 등)
    - **[AI/Backend]** 사용자가 제출한 설문 데이터를 구조화하여 프롬프트로 생성한다.
    - **[AI/Backend]** LangGraph를 사용하여 '설문 분석 -> 필요 영양소 추론 -> 최종 영양제 성분 추천 -> 설명 생성'의 체계적인 단계를 거쳐 결과를 도출한다.
    - **[AI/Backend]** Gemini API에 프롬프트를 전송하고, 추천 성분, 효능, 권장량 등이 포함된 JSON 형식의 응답을 받는다.
    - **[Frontend]** 로딩 인디케이터를 통해 AI가 분석 중임을 시각적으로 표시한다.
    - **[Frontend]** API로부터 받은 JSON 데이터를 파싱하여 결과 리포트(FE-04) 화면에 렌더링한다.
- **Disclaimer:** 서비스 초입과 결과 화면에 "본 서비스는 의료적 진단이나 처방을 대체할 수 없으며, 건강 관련 문제는 전문가와 상의하십시오." 문구를 명확히 고지한다.

**4.2. 복용 스케줄 관리 (FE-05) & 알림 (FE-06)**

- **User Story:** 사용자는 추천받은 영양제를 언제 먹어야 할지 스케줄을 등록하고, 잊지 않도록 시간에 맞춰 알림을 받고 싶다.
- **요구사항:**
    - **[Frontend]** 추천 결과 페이지에서 '스케줄에 추가하기' 버튼을 제공한다.
    - **[Frontend]** 사용자는 영양제별로 복용 시간(아침/점심/저녁 식전/식후)을 설정할 수 있다.
    - **[Backend]** 사용자가 설정한 스케줄 정보를 `schedules` 테이블에 저장한다. (user_id, supplement_id, time 등)
    - **[Backend]** 스케줄링 라이브러리(e.g., APScheduler)를 사용하여 지정된 시간에 푸시 알림 요청을 트리거한다. (실제 푸시는 Firebase Cloud Messaging 등 별도 서비스 사용)
    - **[Frontend]** 사용자는 복용 여부를 체크할 수 있으며, 체크 시 UI에 시각적 변화(체크 표시, 흐린 처리 등)를 준다.
    - **[Backend]** 복용 여부(check-in) 데이터를 `intake_logs` 테이블에 기록한다.

### **5. 기술 스택 및 아키텍처 (Tech Stack & Architecture)**

- **Frontend:**
    - **React.js:** 컴포넌트 기반 아키텍처로 재사용성과 유지보수성이 높으며, 동적인 UI 구성에 용이.
    - **State Management:** Zustand 또는 Recoil (가볍고 직관적인 상태 관리 라이브러리)
    - **Styling:** Styled-components 또는 Tailwind CSS (컴포넌트 단위 스타일링 및 빠른 개발 지원)
- **Backend:**
    - **Flask:** 가볍고 빠르게 API 서버를 구축할 수 있으며, Python 기반으로 AI/ML 라이브러리와의 통합이 용이함.
    - **PostgreSQL:** 안정성과 데이터 무결성이 뛰어나며, JSONB 타입을 지원하여 유연한 데이터 처리가 가능.
    - **ORM:** SQLAlchemy (Pythonic한 DB 조작 및 모델 관리)
- **AI:**
    - **LLM:** **Google Gemini 1.5 Flash API** (비용 효율적이고 빠른 응답 속도로 사용자 경험에 긍정적)
    - **Framework:** **LangGraph** (LLM과의 상호작용을 상태 기반의 그래프(흐름)로 구성하여, 복잡한 AI 에이전트 로직을 체계적으로 관리)
- **아키텍처 다이어그램:**
    
    ```mermaid
    graph TD
        subgraph Client-Side
            User["사용자<br/>(Browser/Mobile)"]
            Frontend["프론트엔드<br/>(React.js)"]
        end
    
        subgraph Server-Side
            Backend["백엔드<br/>(Flask API)"]
            Database[("PostgreSQL DB")]
            AI_Service{{"AI 서비스<br/>(LangGraph + Gemini API)"}}
        end
    
        subgraph External Services
            PushService["푸시 알림 서비스<br/>(FCM/APNs)"]
        end
        
        User -- "UI 사용" --> Frontend
        
        Frontend -- "1. API 요청<br/>(설문 데이터 전송)" --> Backend
        
        Backend -- "2. 분석 요청" --> AI_Service
        AI_Service -- "3. 추천 결과 반환" --> Backend
        
        Backend -- "데이터 읽기/쓰기" <--> Database
        
        Backend -- "4. API 응답<br/>(분석 결과)" --> Frontend
        
        Frontend -- "결과 화면 표시" --> User
        
        Backend -- "알림 예약" --> PushService
        PushService -- "푸시 알림 발송" --> User
    ```

### **6. 디자인 가이드라인 (Design Guideline)**

- **컨셉:** **클레이모피즘 (Claymorphism)**
    - 전반적으로 부드럽고 친근한 인상을 주는 디자인을 채택한다.
    - **주요 특징:**
        - **3D 효과:** 안쪽 그림자(inset shadow)와 바깥쪽 그림자(drop shadow)를 함께 사용하여 둥글고 푹신한 질감을 표현.
        - **색상:** 파스텔 톤의 부드러운 색상을 메인으로 사용하되, 중요한 정보나 CTA 버튼에는 명확한 강조 색상을 사용.
        - **형태:** 모든 UI 요소(버튼, 카드, 입력창)는 둥근 모서리(large border-radius)를 가짐.
        - **배경:** 단색 또는 은은한 그라데이션 배경을 사용하여 요소들이 떠 있는 느낌을 강조.
- **참고 자료:**
    - [Claymorphism in User Interfaces](https://hype4.academy/articles/design/claymorphism-in-user-interfaces)
    - [How to create Claymorphism using CSS](https://hype4.academy/articles/coding/how-to-create-claymorphism-using-css)

### **7. 역할 분담 (Roles & Responsibilities)**

- **프론트엔드 (Frontend):**
    - React.js 기반의 모든 UI/UX 컴포넌트 개발
    - 클레이모피즘 디자인 가이드라인에 따른 UI 구현
    - 상태 관리 로직 설계 및 구현 (Zustand/Recoil)
    - Backend API 연동 및 데이터 처리
    - 사용자 인터랙션 및 애니메이션 구현
    - 담당 기능: FE-01 ~ FE-08의 모든 사용자 인터페이스
- **백엔드 + DB (Backend + DB):**
    - Flask를 이용한 RESTful API 서버 설계 및 개발
    - PostgreSQL 데이터베이스 스키마 설계 및 구축
    - 사용자 인증(JWT 등) 및 인가 로직 구현
    - **AI 연동:**
        - LangGraph를 이용한 AI 분석 파이프라인 설계
        - Gemini API 호출 및 응답 데이터 가공 로직 개발
    - 복용 스케줄 및 알림 관련 비즈니스 로직 구현
    - 서버 배포 및 관리
    - 담당 기능: FE-01 ~ FE-08의 서버 로직, DB, AI 연동
